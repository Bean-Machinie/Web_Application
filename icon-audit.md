# Icon audit

## Summary

- **Main library: `lucide-react` ^1.48.0** (`components.json` sets `"iconLibrary": "lucide"`). About 140 files import it.
- **Local SVG icons:** `src/assets/icons/*.svg`, rendered through `src/components/Icon.tsx`. It masks the SVG over `currentColor`, because the files hard-code a black stroke.
- **Hand-built animated icons:** `src/components/AnimatedIcon.tsx` (an `IconHandle` with `startAnimation`/`stopAnimation`), `BellIcon.tsx` and `PlusIcon.tsx`. They are rendered by `IconButton.tsx`, in `NotificationBell` (bell) and `CreateMenu` (plus). These are the only animated icons.
- **Custom lucide icons:** `map-erase-icons.ts` (`createLucideIcon` "paintbrush-off") and `map-land-icons.tsx` (`LassoIcon`, lasso plus a +/− badge). Lucide has no such icons, so they need hand-built equivalents.
- **No other icon libraries** (no react-icons, heroicons, etc.). No AnimateIcons yet. Emoji and image assets (`public/templates`, `src/assets/map-assets`) are artwork, not icons.

**About the suggestions.** AnimateIcons (animateicons.in) ships a Lucide set (669 icons, shadcn command `npx shadcn@latest add @animateicons/lu-<name>`) and a Huge set (501). I could not load its full icon list. Every "suggested replacement" below is therefore the `lu-` icon with the same name as the current lucide icon, and each one needs checking against the catalog before use. "no match likely" means the icon is unlikely to exist, or is custom.

Where several icons sit in one file, each is listed as `Icon` (usage). `ui/` files are generated by shadcn and use the `…Icon` alias names.
